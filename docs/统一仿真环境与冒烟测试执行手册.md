# 统一仿真环境与冒烟测试执行手册（mani_skill 装进 .venv-lerobot）

负责人：仿真与接口工程师　日期：2026-10-13　执行者：用户本地助手（ducks-OMEN，RTX 5070 Laptop）

## 0. 目标
让 B0 评测和残差 PPO 能在**同一个进程**里同时跑 ManiSkill 仿真和冻结的 SmolVLA：
- `.venv-lerobot`（Python 3.12，lerobot 0.6.1，numpy≥2）作为**主环境**，额外装 mani_skill 3.0.1；
- `.venv-ms3`（Python 3.11，numpy<2，mplib）**保留不动**，只用来采运动规划示范。

## 1. 已核实的依赖事实（来源：PyPI 的 mani_skill-3.0.1 wheel METADATA，box 上实际解包查看）
- `Requires-Python >=3.9`，`numpy>=1.22`：版本本身不挡 3.12 和 numpy 2。
- **`mplib==0.1.1`（Linux 硬依赖）**：mplib 0.1.1 需要 numpy<2，所以**直接 `pip install mani_skill` 会把 numpy 降级，破坏 lerobot**。
- 结论：用 `--no-deps` 装 mani_skill，再手动装除 mplib 以外的依赖。
- 工程里只有 `gen_mp_demos_rebot.py` 真正用 mplib（采集，留在 .venv-ms3）；环境 `PickCubeReBot-v1` 和 `eval_b0_rebot.py` 不 import mplib。
- **未验证**：sapien 3.x 在 numpy 2 下能否正常运行；mani_skill 内部是否有模块在导入时顺带 import mplib。这是第 3 步要验证的核心。

## 5. 常见报错
| 现象 | 处理 |
|---|---|
| 安装时解析器要求 numpy<2 | 说明有包间接拉了 mplib。停下，查 freeze 差异，不要强装 |
| `No module named mplib` 出现在 import mani_skill 时 | 记下 traceback 里的模块名，交给仿真与接口工程师判断能不能绕过（比如延迟导入） |
| sapien 报 numpy ABI 或 dtype 错误 | sapien 和 numpy 2 不兼容，转第 6 节的备选方案 |
| Vulkan、渲染相关错误 | 确认 `nvidia-smi` 正常、装了 libvulkan1，再跑 `python -m mani_skill.utils.sapien_utils` 之类的自检，或者把报错交回来 |
| `max_steps 200` | OMEN 上的环境文件是旧版，核对 md5 |

## 6. 需要用户拍板的决策点
1. **装不上时选哪个备选方案**（只在第 3 节第 2 或第 3 步失败时才需要决定）：
   - A. 两个进程：仿真留在 .venv-ms3，SmolVLA 在 .venv-lerobot，通过本地 socket 或共享内存传观测和 a_base。环境不冲突，但每步多一次通信延迟，PPO 吞吐会下降（具体多少待实测）。
   - B. 降级 lerobot 到支持 Python 3.11 的旧版本。不推荐：VLA 研究员已经确认旧版会把 torch 降级，而且整套微调命令都要按旧接口重写。
   - 我的建议是 A。
2. **D405 视场角**：用 Intel 官方标称值替换 58° 占位，还是暂时保留占位。改了会影响所有相机图像，必须在微调之前定。
