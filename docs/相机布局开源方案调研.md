# Camera Layout Survey — OpenArm head+wrist vs peers

**Date:** 2026-10-12 (Asia/Shanghai)  
**Scope:** Documentation-only survey. **No MJCF / contract extrinsics were changed.**  
**Vendor pin:** `openarm_mujoco` @ `0e050bb5d3472b75c6bfa00b310a77c7c2c5be79`  
**Current project layout:** local overlay copies v2 cell `camera_head_right` (worldbody) + v2 `camera_wrist_right` onto v1 single-arm (`scene_single_arm.xml` / `openarm.xml`). User reports this layout is wrong.

Smoke evidence (already in-repo): `logs/camera_smoke/head.png` looks past the gripper onto empty floor; `logs/camera_smoke/wrist.png` looks into joint geometry (parent-frame mismatch), not the workspace.

---

## 1. One-sentence conclusion

**Official OpenArm “head” is a cell-fixture (worldbody) stereo pair at enclosure head height — not a robot head link — and pasting those absolute cell numbers onto a bare-floor v1 single-arm (plus v2 wrist numbers on v1 `openarm_hand`) is not a valid OpenArm or industry layout; keep numbers frozen until a scene that matches the cited parent frame is adopted.**

## 3. Industry “wrist + head/external” layouts (peers)

User expectation “手腕+头部” maps, in practice, to **one eye-in-hand + one ego/external workspace view**. Naming differs; **“head” is OpenArm-cell-specific**. Peers usually say front / top / agentview / overhead — and **overhead is not OpenArm head** (OpenArm head ≠ ceiling).

| Family | External / “global” | Wrist | Body-fixed? | Fits OpenArm v1 single-arm? |
|--------|---------------------|-------|-------------|------------------------------|
| **OpenArm cell (official)** | `head_left/right` (+ optional `ceiling`) | `wrist_*` on `ee_base_link` | head: worldbody; wrist: body | Only if **cell frame** (or equivalent height) is present |
| **OpenArm hardware** | **chest** D435 on pillar | D405 wrist | chest: fixture; wrist: body | Needs pillar / chest mount in scene |
| **OpenArm pedestal tasks** | `frontcam`, `tablecam` | (wrist only if robot XML includes it) | worldbody | Numbers are for pedestal+table @ ~0.4 m — still not “head” |
| **SO-100/101 + NVIDIA sim2real** | `front` (stationary) | `wrist` | front: fixed; wrist: body | **Best peer for single desktop arm VLA** |
| **gym-so100** | `top`, `angle`, pillars | jaw cam TODO | worldbody `targetbody` table | top ≠ head; no wrist in scene.xml yet |
| **ALOHA / ACT sim** | `overhead_cam`, `worms_eye_cam` | `wrist_cam_left/right` | overhead/front: world; wrist: gripper | Bimanual; overhead ≠ OpenArm head |
| **LIBERO (Franka)** | `agentview_image` | `robot0_eye_in_hand_image` | agentview fixed; EIH body | Conceptually wrist+external |
| **ManiSkill** | `base_camera` (task-dependent) | `panda_wristcam` robot | mixed | Wrist optional via robot UID |
| **ReBot B601** | `overhead_rgb` topic | D405 wrist mounts + MuJoCo previews | overhead: scene; wrist: end | Desktop arm; **overhead ≠ head** |

## 5. Why the current local overlay fails (without inventing new numbers)

Current contract (`openarm_residual_gate/contract.json`):

- `head` ← exact `camera_head_right` pos/xyaxes/fovy from cell worldbody, placed in **v1 floor** `scene_single_arm.xml`.
- `wrist` ← exact `camera_wrist_right` pos/euler/fovy from v2, parent **`openarm_hand`** (v1), while upstream parent is **`openarm_right_ee_base_link`** (v2).

Failures observed:

1. **Frame mismatch (head):** cell `z=1.45` assumes cell furniture/lifter; v1 arm base ≈ floor → head view is a high downward look at empty checkerboard (smoke `head.png`).
2. **Parent mismatch (wrist):** same local transform on wrong body → smoke `wrist.png` shows joint internals, not the grasp workspace.
3. **Naming vs hardware:** official physical non-wrist cam is **chest**; sim dataset “head” is cell stereo — neither is a robot head link.

This validates the user: **numbers are “official” but the scene/parent they belong to are not the ones we attached them to.**

## 6. Three candidate layouts (sourced) — **do not apply yet**

Per task rule: **do not change engineering extrinsics** unless a clearer OpenArm **v1 single-arm** official layout appears. Below are candidates for a later decision.

### Candidate A — OpenArm-faithful cell (head_right + wrist_right)

- **Cameras:** `camera_head_right` + `camera_wrist_right` (optionally add ceiling later; keep names distinct).
- **Mount:** head = cell worldbody; wrist = v2 `ee_base_link` (or migrate robot to v2).
- **Excerpt:** §2 cell.xml + openarm_bimanual.xml above.
- **Pros:** Matches official OpenArm sim, Dora, HF datasets, naming `head`/`wrist`.
- **Cons / risk:** Requires **cell (or height-matched) scene**; not a floor-only v1 include. Single-arm must still sit in cell frame. Bimanual datasets ≠ unimanual residual obs.
- **v1 usability:** Only after scene upgrade (cell attach / v2 single-arm path), not by pasting coords.

### Candidate B — Desktop-arm VLA peer (wrist + front/external) — SO-101 style

- **Cameras:** body wrist + worldbody `front` (or `angle`) looking at table workspace.
- **Excerpt (keys / convention):** NVIDIA SO-101 teleop uses `"wrist"` + `"front"`; gym-so100 uses table-targeted `angle`/`top` (cite §3).
- **Pros:** Matches what most single-arm SmolVLA/ACT stacks call “wrist+global”; works on tabletop without cell; ReBot overhead+wrist is the same idea (name overhead carefully).
- **Cons / risk:** **Not** official OpenArm naming; if LeRobot keys stay `observation.images.head`, must document that `head` means “external/front”, **not** OpenArm cell head and **not** ceiling. Extrinsics must be designed vs **our** table/base — cannot invent numbers here.
- **v1 usability:** Conceptually yes; needs measured/designed extrinsics for this scene (out of scope until approved).

### Candidate C — OpenArm pedestal task pair (frontcam + tablecam) + wrist

- **Cameras:** official pedestal `frontcam` / `tablecam` numbers from e.g. `move_puck_scene.xml`, plus a wrist on the correct EE body.
- **Excerpt:** §3 pedestal snippet; table top note `z=0.40` vs cell `z=1.005`.
- **Pros:** Still Enactic MJCF; frontcam is a true workspace external view.
- **Cons / risk:** `tablecam` is near-overhead — **must not be labeled `head` without a note**; still requires pedestal+table geometry; wrist parent issue remains on v1.
- **v1 usability:** Only with pedestal/table scene, not bare floor.

| Priority | Choice | Why |
|----------|--------|-----|
| **Now** | **Freeze extrinsics** (A-numbers already in tree, but treat as **non-authoritative for v1 floor**) | No clearer official **v1 single-arm** layout found; changing numbers without a matching scene would still be wrong. |
| **If OpenArm sim2real / dataset align is the goal** | **Candidate A** — move residual env to **v2 cell (or height-matched cell frame)** and keep official `camera_head_right` + `camera_wrist_right` with correct parents | Only path that preserves OpenArm “head” semantics without lying. |
| **If single-arm residual/VLA peer benchmarking is the goal** | **Candidate B** — wrist + external front; rename/document keys; design extrinsics against the actual table | Matches SO-101 / ReBot / LIBERO pattern; do **not** call ceiling “head”. |
