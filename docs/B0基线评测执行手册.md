## 0. 目标
1. **管线冒烟**：用 `--policy hold` 跑通 reset→step→落盘，确认输出文件齐全。
2. **SmolVLA 冻结推理评测**：用微调后的 checkpoint、δ=0，在测试 seed（从 10000 起）上得到成功数 k/n 和 Wilson 95% 区间。
3. 按《ReBot基线B0判定标准》给出三选一结论：回去改 base / 不训残差 / 进入残差冒烟。**阈值 p_lo、p_hi 和判定用的 n 由用户定，本手册不预填。**
4. 对每条失败 episode 做失败分类，并核查成功判定有没有误判。

`scripts/eval_b0_rebot.py` 的行为：
- 参数：`--policy {hold,smolvla}`、`--ckpt`、`--task`、`--n-action-steps`、`--env-id`（默认 PickCubeReBot-v1）、`--n-episodes`（默认 5）、`--seed-start`（默认 10000）、`--max-steps`（默认取环境注册值 300）、`--cam-rand`、`--out`（默认 `logs/b0_rebot`）。
- 第 i 条 episode 用 seed = seed-start + i。
- 输出：`run_manifest.json`（argv、参数、python/numpy/torch/mani_skill/sapien 版本、GPU、git commit、时间）、`episodes.jsonl`（每条的 seed、error、success、ever_success、steps、wall_s、failure_mode="unlabeled"）、`summary.json`（n、successes=k、rate、wilson95=[lo,hi]、seeds、cam_rand）、`diag_ok_<seed>.npz` / `diag_fail_<seed>.npz`。
- diag npz 的逐步字段：`qpos, action, lift_height, is_grasped, contact_force_left, contact_force_right, hold_count, success, reward`；另有首末帧 `first_wrist/first_overhead/last_wrist/last_overhead`。smolvla 模式额外有 `chunk_idx, phase, latency_vla_ms`。
- **注意两个口径**：`summary.successes` 统计的是**最后一步的** `success`；文件名的 ok/fail 用的是 `ever_success`。成功后环境不会自动 terminate 时两者可能不同，见第 5 节决策点 D5。
- `--cam-rand` 目前**只是记进 summary 的标志，脚本和环境都没有实现相机随机化**。范围待用户定（D4），实现前不要拿带这个标志的结果当随机化评测。

### 步骤 5：失败分类与误判核查
```bash
python - <<'PY'
import glob,json,numpy as np
D="logs/b0_rebot/smolvla_n<n>"   # 换成实际目录
FMIN=0.5   # 与环境的 grasp_min_force 占位值一致，只用于分类
rows=[]
for f in sorted(glob.glob(f"{D}/diag_*.npz")):
    z=np.load(f); seed=int(f.split("_")[-1][:-4]); g=z["is_grasped"]>0.5; L=z["lift_height"]
    fmax=np.maximum(z["contact_force_left"],z["contact_force_right"])
    fl=z["action"][:,6]
    r=dict(seed=seed, file=f.split("/")[-1], steps=len(L), max_lift=float(np.nanmax(L)), max_hold=int(np.nanmax(z["hold_count"])),
           any_grasp=bool(g.any()), any_contact=bool((fmax>FMIN).any()), min_cmd_finger_left=float(fl.min()),
           grasp_then_lost=bool(g.any() and not g[-1]), ever_success=bool((z["success"]>0.5).any()),
           nan=bool(np.isnan(z["action"]).any()))
    if r["ever_success"]: mode="success"
    elif r["nan"]: mode="nan_or_error"
    elif not r["any_contact"]: mode="未接近/未接触"
    elif not r["any_grasp"]: mode="接触但未合爪(抓空)"
    elif r["grasp_then_lost"]: mode="合爪后掉落"
    elif r["max_lift"] < 0.05: mode="合爪但未抬到5cm"
    else: mode="抬到5cm但保持不足10步/超时"
    r["auto_mode"]=mode; rows.append(r)
json.dump(rows, open(f"{D}/failure_auto.json","w"), indent=1, ensure_ascii=False)
from collections import Counter; print(Counter(r["auto_mode"] for r in rows))
print("误判核查: fail 文件里 max_lift>=0.05 且 max_hold>=10 的:", [r["seed"] for r in rows if r["file"].startswith("diag_fail") and r["max_lift"]>=0.05 and r["max_hold"]>=10])
print("误判核查: ok 文件里 max_lift<0.05 的:", [r["seed"] for r in rows if r["file"].startswith("diag_ok") and r["max_lift"]<0.05])
PY
```
- 自动分类只是初筛，**每条失败样本都要看首末帧图像，人工确认** failure_mode，写进 `failure_manual.json`（字段：seed、auto_mode、manual_mode、备注）。
- 分类类别：未接近/未接触、接触但未合爪（抓空）、合爪后掉落、合爪但未抬到 5 cm、抬起但保持不足 10 步或超时、NaN/异常。`FMIN` 是环境里的占位阈值，不是标定值。
- **误判核查**（判定标准里的待复核项）：①失败 episode 的最大抬升 `max_lift` 达到 0.05 m 且 `max_hold ≥ 10` 的，说明成功判定或落盘口径有问题；②标成成功、但最大抬升不到 0.05 m 的，也说明有问题。两个列表都应为空，不为空就上报，暂停判定。
- 额外看一下：失败样本里 `max_lift` 的分布，以及 `合爪前 lift_height` 是否为 0（示范里是 0）。如果没合爪方块就升高了，可能是被推动或穿模，要上报。

## 4. 常见报错与处理
| 现象 | 处理 |
|---|---|
| `max_episode_steps unknown` | 环境没注册，或者 md5 不对。核对 md5，别用 `--max-steps` 硬绕过 |
| `[b0] T=200` | OMEN 上的环境文件是旧版 |
| `--policy smolvla needs --ckpt` | 补上 `--ckpt` |
| `cannot load pre/post processors` | ckpt 目录不对（要指到含 `config.json`、`model.safetensors` 和 processor 文件的那一层，一般是 `pretrained_model/`），或者 lerobot 版本里的函数名不同。把完整报错和 `ls $CKPT` 交回来，**不要跳过归一化** |
| `Missing features: observation.images.camera3` | 微调时用了 `--policy.empty_cameras=1` 的话，ckpt 自带配置，按报错把信息交回来；脚本不擅自补空图 |
| `KeyError: observation.images.wrist` 或相机键不匹配 | 说明 processor 期望的是重命名前的键名。交回来，由脚本侧改 `CAM_MAP` |
| `size mismatch` / state 维度 6 vs 7 | 停下上报，不要改维度（VLA 手册同样要求） |
| `non-finite a_base` | 记下 seed 和 t，上报；diag 已经落了前面的步 |
| 动作量级明显不对、机械臂一开始就猛甩 | post-processor 的反归一化没生效。停下，交回 action min/max |
| CUDA OOM | 先关掉其他 GPU 进程再重跑；还不行就把 `logs/b0_gpu_smoke.csv` 交回来 |
| `no kernel image is available` / sm_120 | torch 不是 cu128 构建，回到 VLA 手册重装 |
| Vulkan、渲染错误 | 按《统一仿真环境》手册第 5 节处理 |

## 6. 需要用户拍板的决策点
| # | 决策 | 候选与理由 | 状态 |
|---|---|---|---|
| D1 | p_lo、p_hi | 判定标准明确不预设。理由：阈值取决于残差能纠正多大差距，以及你对"base 已够好"的定义 | **待用户定** |
| D2 | 判定用 n | 冒烟 n=5 只用于跑通流程。n 越大 Wilson 区间越窄，耗时 ≈ n × 第 3 步实测的平均 wall_s。建议等第 3 步耗时出来后，按"区间宽度能否把结果和 p_lo/p_hi 分开"来定 | **待用户定** |
| D3 | 用哪个 checkpoint 当 base | `last` 或者某个中间步的 ckpt。必须在评测前定好并写进报告，不能评完再挑 | **待用户定** |
| D4 | 相机随机化范围 | 相机随机化还没实现（`--cam-rand` 只是一个标志）。候选：A 不随机化，先拿名义相机出 B0；B 小幅扰动 overhead 位姿和 wrist fov（幅度待定）。理由：wrist fov 现在是 58° 占位，overhead 也没有实测标定 | **待用户定**（范围不预填） |
| D5 | 成功口径用"最后一步 success"还是"ever_success" | 脚本现在 k 用的是最后一步，文件名用的是 ever。判定标准原文是"episode 结束时 success；另记 ever_success"。建议保持现状、两个都报；如果两者差距明显就上报 | 待用户确认 |
| D6 | D405 fov 是否换成官方值 | 沿用《统一仿真环境》手册 D2。改了会让 base 的输入分布变化，必须在 B0 之前定 | 待用户定 |
